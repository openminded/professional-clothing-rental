# App Flow Document for Professional Clothing Rental Management System

## Onboarding and Sign-In/Sign-Up
When a new user arrives at the system, they first see a clean landing page with an introduction to the professional clothing rental service. From there, they can choose to create an account using their email and a secure password. The sign-up screen asks them to enter their name, email address, and password, and then click a button to verify their email. Once the email is verified, the user is prompted to select their role: Cashier or Manager. After selecting a role, they complete a brief profile setup with optional information such as phone number and work location.

For returning users, the sign-in page allows them to enter their email and password to access the system. If a user forgets their password, a link on the sign-in page leads them to a password recovery flow. They enter their email and receive a reset link by email, which directs them back to a secure form to set a new password. Once the password is updated, they can sign in again. Every authenticated session includes a visible sign-out button, which returns the user to the landing page and clears their session securely.

## Main Dashboard or Home Page
After signing in, the user lands on a dashboard that differs slightly depending on their role. A Cashier sees the Point of Sale home view, while a Manager sees an overview of reports. Both dashboards share a common layout with a top header that displays the user’s name, role, and a sign-out button. Along the left side, a vertical navigation menu lists the main sections: POS, Inventory, Returns, and Reports. The styling adapts automatically between light and dark mode.

In the POS dashboard, the center panel features a search bar for clothing items, a live inventory list, and a cart summary area. In the Inventory section, a data table shows all clothing models and individual items with controls to add or edit entries. In the Returns section, a return form shows active rentals and allows the user to process item returns. In the Reports section, managers see interactive charts, date range selectors, and summary cards for revenue, rentals, and inventory availability. Clicking any menu item instantly loads the corresponding page while preserving the navigation menu and header.

## Detailed Feature Flows and Page Transitions
### Point of Sale Flow
A Cashier begins by clicking the POS link in the sidebar. The POS page loads the latest inventory status. The user types keywords into the search box to filter items by style or size. As items appear, the user clicks an item to add it to the cart. The cart summary instantly updates with item thumbnails, rental period, and subtotal. When all items are in the cart, the user clicks the payment button, which opens a dialog for choosing payment method. After entering payment details and confirming, the system calls the rentals API. The API locks the selected items, creates the rental record, and updates each item status to “Rented.” A confirmation message appears with a printable receipt. The user can click a print icon to open the browser’s print dialog.

### Inventory Management Flow
Managers or Cashiers with permissions click the Inventory menu. The inventory page fetches all clothing models and items from the server. Each row has an edit icon. Clicking edit opens a modal form prefilled with item details. The user can change fields such as size, color, or availability status, and then submit the form. Submissions call the inventory API route to update the database and then refresh the table. To add a new item, the user clicks an add button, which opens a blank form. After entering the item information and saving, the new item appears in the list. If the user navigates away and then returns to the inventory page, the refreshed data reflects the latest state.

### Return Processing Flow
When items come back, the Cashier goes to the Returns page by selecting it in the sidebar. The page lists active rentals with due dates. The user selects the rental to return and clicks a process button. A return form shows each item in the rental. The Cashier can inspect each item and mark it as returned. If the return is late, the system automatically calculates late fees. After confirming the return, the form submission calls the rentals API to update the rental record, mark items as “Available,” record any extra charges, and log the action. A success banner confirms the return process is complete and offers the option to view or print an updated receipt.

### Reporting and Analytics Flow
A Manager visits the Reports page by clicking the Reports link. The page displays date range selectors at the top. After selecting start and end dates and clicking apply, the page queries the reporting API. The API runs database aggregations for revenue, item usage, and availability statistics, then returns data for charts and tables. The charts render showing revenue trends and the tables list the most rented items or customers. The Manager can click on any chart segment or table row to drill into detailed views, such as individual transaction history. They can also export the table data as a CSV file via a download button.

## Settings and Account Management
From the header, any user can click their profile name to open account settings. On the settings page, they can update personal details such as name, email, and phone number. They can also change their password by entering the current password, a new password, and confirming it. A toggle switch lets them enable or disable email notifications for events like completed returns or low inventory alerts. After saving, a confirmation message appears. To return to the main workflow, the user clicks a “Back to Dashboard” link in the sidebar, which takes them back to the correct home view for their role.

## Error States and Alternate Paths
If a user enters invalid data in any form, the system highlights the affected fields in red and shows a clear error message describing the issue, such as "Please enter a valid email address" or "Inventory item name is required." If the network connection is lost while the app is fetching data, a full-screen banner appears stating "Connection lost. Retrying…" Once connectivity returns, the banner disappears and data refreshes automatically. In the POS flow, if two cashiers try to rent the same item at the same time, the API returns a booking conflict error. The front end shows a modal with the message "Item X was just rented by another user. Please refresh and try again." The user then reloads the inventory list and restarts the flow. For any server errors, a generic page appears with "Something went wrong" and a button to return to the last known safe page.

## Conclusion and Overall App Journey
From the moment a user signs up and picks a role, they enter a coherent world of rental management. Cashiers can swiftly rent out items, process returns, and keep inventory up to date, all from a clear POS interface. Managers can oversee inventory, update item details, and dive into financial and usage reports. Throughout every step, the system guards data integrity with transactional operations and guides users with friendly messages. Whether fixing a profile setting, tackling a network hiccup, or exporting a revenue report, the user always knows exactly where they are and what to do next, from sign-up through daily operations and back to the dashboard.
